# Copy 本地剪贴板工具设计

## 产品定位

Copy 是一款轻量级 Mac 剪贴板历史工具。它会记录用户在本机复制过的内容，并帮助用户快速找回和复用之前复制过的文字、链接、图片等信息。

第一版定位为纯本地工具：

- 不需要账号。
- 不做云同步。
- 不上传剪贴板内容。
- 不做远程分析。
- 不依赖服务器。
- 所有剪贴板历史只保存在用户自己的 Mac 本地。

## 目标用户

目标用户是高频使用 Mac 的用户。他们经常在聊天工具、浏览器、文档、设计工具、开发工具之间切换，需要随时找回之前复制过的内容。

产品气质应该安静、轻量、工具化。平时不打扰用户，只在用户需要找历史内容时出现。

## 第一版 MVP 范围

第一版只需要把五件事做好：

1. 自动记录用户复制过的文字、链接和图片。
2. 所有记录都保存在用户本地。
3. 通过全局快捷键打开一个紧凑的历史面板。
4. 支持搜索和预览剪贴板历史。
5. 选中历史记录后，可以一键重新复制到系统剪贴板。

## 第一版不做的功能

为了保持产品简单，第一版不做：

- iCloud 同步。
- 多设备同步。
- 用户账号。
- 图片 OCR 识别。
- AI 自动分类。
- 共享剪贴板历史。
- 团队协作功能。
- 浏览器插件。
- 自动识别和过滤敏感内容。

这些能力都可以后续再考虑。第一版的重点是先做成一个稳定、可信、好用的本地剪贴板工具。

## 核心交互

Copy 以菜单栏应用的形式常驻。

菜单栏入口包含：

- 打开剪贴板历史。
- 暂停记录。
- 清空全部历史。
- 设置。
- 退出。

用户也可以通过全局快捷键打开剪贴板历史面板。建议默认快捷键为 `Command + Shift + V`，如果和用户已有快捷键冲突，可以在设置里修改。

历史面板包含：

- 顶部搜索框。
- 中间历史列表。
- 内容预览区域，或者在列表中直接做轻量预览。
- 键盘操作支持，例如上下选择、回车复制。

主要使用流程：

1. 用户在任意应用中复制内容。
2. Copy 检测到系统剪贴板变化。
3. Copy 把内容标准化后保存为本地记录。
4. 用户按全局快捷键打开历史面板。
5. 用户搜索或浏览最近复制的内容。
6. 用户点击某条记录，或者按回车选中。
7. Copy 把该记录重新写回系统剪贴板。

## 支持的剪贴板类型

### 文字

普通文字直接存入本地数据库。历史列表中展示第一行内容和简短摘要。

### 链接

链接本质上仍然按文字保存，但界面上要识别并显示为链接类型。第一版可以直接展示 URL 本身，不需要额外抓取网页标题。

### 图片

图片不建议直接存入数据库。推荐把图片文件保存到本地应用目录，数据库只保存图片路径、缩略图路径和基础元数据。

历史列表中展示图片缩略图。如果能拿到尺寸信息，可以展示图片宽高。

## 本地存储

推荐存储位置：

```text
~/Library/Application Support/Copy/
```

推荐目录结构：

```text
Copy/
  copy.sqlite
  Images/
    original/
    thumbnails/
```

SQLite 用来保存结构化元数据，图片原图和缩略图单独以文件形式保存。

建议的历史记录字段：

```text
id
type
preview
plainText
url
imagePath
thumbnailPath
sourceAppBundleId
sourceAppName
contentHash
createdAt
lastUsedAt
useCount
isFavorite
```

## 去重规则

Copy 应该避免在短时间内重复保存完全相同的内容。

第一版去重规则：

- 根据标准化后的内容生成 `contentHash`。
- 如果最新一条记录和当前复制内容的 hash 相同，只更新时间，不新增重复记录。
- 如果更早的历史记录和当前复制内容的 hash 相同，更新那条旧记录，把它移动到历史列表顶部，并增加使用次数，不插入新的重复记录。

## 隐私与信任边界

Copy 默认记录所有剪贴板内容，因为它的产品定位是纯本地工具。

信任边界：

- 剪贴板历史只保存在用户自己的 Mac。
- 应用不上传剪贴板内容。
- 应用不需要登录。
- 应用不发送包含剪贴板内容的分析数据。

用户控制能力：

- 暂停记录。
- 删除单条记录。
- 清空全部历史。
- 限制历史保留数量。
- 退出应用。

推荐设置项：

- 只保留最近 500 条。
- 只保留最近 1000 条。
- 永久保留。
- 清空历史时同时删除图片缓存。

## 设置项

第一版设置包括：

- 全局快捷键。
- 最大历史保留数量。
- 开机启动。
- 暂停记录状态。
- 清空全部历史。

后续可以增加“不记录某些应用”的高级规则，但这不是 MVP 必需功能。

## 模块架构

### ClipboardMonitor

负责监听 macOS 系统剪贴板变化，并提取支持的内容类型。

职责：

- 监听或轮询剪贴板变化计数。
- 忽略 Copy 自己写回剪贴板产生的变化。
- 标准化识别到的内容。
- 把新内容交给存储层。

### ClipboardStore

负责保存和查询剪贴板历史。

职责：

- 插入或更新历史记录。
- 管理去重逻辑。
- 搜索历史记录。
- 删除历史记录。
- 执行历史数量保留限制。

### ImageStore

负责把图片原图和缩略图保存到本地磁盘。

职责：

- 保存复制得到的图片。
- 生成缩略图。
- 删除历史记录时同步删除图片文件。
- 保持数据库路径和磁盘文件一致。

### HistoryPanel

负责剪贴板历史主界面。

职责：

- 展示最近复制记录。
- 搜索文字和链接记录。
- 展示图片缩略图。
- 支持键盘导航。
- 把选中的历史记录恢复到系统剪贴板。

### MenuBarController

负责菜单栏入口和菜单操作。

职责：

- 展示应用状态。
- 打开历史面板。
- 暂停或恢复记录。
- 清空全部历史。
- 退出应用。

### PasteboardWriter

负责把历史内容重新写回系统剪贴板。

职责：

- 按正确的剪贴板类型恢复文字、链接和图片。
- 标记由 Copy 自己产生的剪贴板写入，避免监听器立刻生成重复记录。

## 异常处理

读取剪贴板失败时，不要打扰用户，静默跳过即可。

如果本地数据库无法打开，应用应该给出明确错误提示，不能假装正在正常保存历史。

图片写入失败时，不应影响文字和链接记录继续工作。

清空历史时，需要同时删除数据库记录和本地图片文件。

## 测试策略

单元测试：

- 文字标准化。
- URL 识别。
- 内容 hash 生成。
- 去重逻辑。
- 历史数量保留规则。

集成测试：

- 插入和查询文字记录。
- 插入图片元数据，并删除关联图片文件。
- 将文字恢复到系统剪贴板。
- 确认 Copy 自己写回剪贴板时不会生成重复记录。

手动 QA：

- 从备忘录、浏览器、聊天工具、代码编辑器复制文字。
- 从浏览器地址栏和网页正文复制链接。
- 从浏览器和 Finder 复制图片。
- 使用全局快捷键打开历史面板。
- 搜索历史记录。
- 恢复历史记录并粘贴到其他应用。
- 暂停记录后确认新复制内容不会被记录。
- 清空历史后确认图片文件也被删除。

## 初始开发里程碑

### 里程碑 1：本地文字剪贴板历史

- 菜单栏应用外壳。
- 剪贴板监听器。
- 本地 SQLite 存储。
- 文字记录捕获。
- 基础历史面板。
- 恢复文字到系统剪贴板。

### 里程碑 2：链接识别与搜索

- URL 识别。
- 搜索框。
- 更好的记录摘要。
- 键盘导航。
- 去重逻辑。

### 里程碑 3：图片历史

- 图片提取。
- 图片本地文件存储。
- 缩略图生成。
- 图片列表预览。
- 恢复图片到系统剪贴板。

### 里程碑 4：设置与控制

- 自定义全局快捷键。
- 开机启动。
- 暂停记录。
- 删除单条记录。
- 清空全部历史。
- 历史数量限制。

## 推荐技术栈

- Swift。
- SwiftUI。
- AppKit，用于菜单栏、系统剪贴板和全局快捷键等能力。
- SQLite，用于保存历史元数据。
- 本地文件系统，用于保存图片。

这套技术栈能保证应用有原生 Mac 体验，同时避免引入不必要的运行时依赖。

## 后续产品决策

以下决策可以留到实现计划阶段再定：

- 应用最终名称和图标。
- 如果 `Command + Shift + V` 冲突，默认快捷键改成什么。
- 历史面板采用浮层、弹窗还是小窗口。
- 收藏功能是否进入第一版，还是放到第二版。
